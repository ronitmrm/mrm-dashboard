# PDFKit migration verification — issue 152

Verified 2026-09-19 on `perf/compute-optimization`, rebased onto staging
`daa2fdc7`. Local production-equivalent Vercel function bytes decreased from
**385,206,247 to 94,429,671**: **290,776,576 bytes / 75.49% less**.
No deployment, retention or paid-setting changes were made.

Vercel CLI 59.16.0 and its `@vercel/next` 12.0.0 builder, identical project
settings and local test environment. The before copy retained the Chromium

## Representative output and performance

The same six normalized fixtures in `verification-fixtures.ts` were generated by
both renderers on the same Linux host. Each fresh measurement starts a child
process; render time excludes process startup. Peak RSS samples the whole process
tree every 25 ms, including Chromium children, and can miss shorter peaks.
Measurements are one local capture, not production percentiles or an SLA.

Twelve renders in one process (two rounds of the six fixtures): total wall time
**4,492.05 → 1,000.32 ms**, peak process-tree RSS **486.4 → 190.2 MiB**.
All samples are below the 5 MiB output cap and preview's 60-second limit.
Local RSS is not proof of an unmeasured deployed memory limit.

Print-scale raster inspection covered all five single-page posters and all nine
pages of the paired SOP book. Reviewed Indic conjuncts/matras/digits, baselines,
real font weights, banner and wordmark proportions, margins, picture crop versus
contain, grid captions, list flow and index destinations. Changed wrapping was
reviewed against fixed regions and approved typography; pixel equality is not an
acceptance criterion. Stage 6 stays with its first paragraph on printed page 5;
stage 12 is on printed page 7 and its index agrees. One existing-test variation
covers two language books and a multipage index. The same fixture was also
rendered as Policy with both implementations (nine pages each); cover, details,
index, opening body and final page were inspected separately. Its label/metadata,
frame, fixed typography and list continuation retain the shared book design.

The font gate uses the actual bundled fonts at final print sizes. Two Fontkit
2.0.4 subset-encoder defects required a pinned patch: Restructure 3 buffer
allocation and a missing final repeated-point flag count. The latter made commas
extractable but visually absent; the output test now checks the embedded outline
against the source. Distinct variable-weight PostScript names prevent PDFKit from
deduplicating different weights. Saved bold, italic and underline survive.
Unsupported glyphs reject. PDF.js can extract some Indic marks in
visual/decomposed order despite `ActualText`; exact source-order copying is not
claimed. See [font notes](../../apps/web/lib/branding/assets/README.md).
